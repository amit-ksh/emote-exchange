## Measured performance

OBS canvas/output: 1920×1080 at 60/1; Browser Source custom FPS: 60. Local software x264 recording, not a Twitch stream. The initial normal-mode 103.07-second recording (`2026-10-29 20-19-07.mp4`) reported 6,243 drawn frames out of 6,245 attempted, two rendering stalls (rounded 0.0%). OBS Stats showed 60 FPS, approximately 5–5.8 ms render time and zero encoding skips; its cumulative setup counter included 32 missed frames, which is not presented as zero.

OBS was later reopened after an unclean shutdown notice in its diagnostic Safe Mode. Its built-in Browser Source remained available. The 204.15-second bright/full/half/reduced capture (`2026-10-29 22-51-26.mp4`) reported 12,282 drawn frames out of 12,283 attempted and one rendering stall (rounded 0.0%). The 96.52-second boundary recording reported 5,823 drawn frames and no rendering stalls. These are measured runs on this machine, not a guarantee of uninterrupted 60 FPS on other hardware.

Used a temporary same-origin browser timing harness in ignored build assets, sampling the actual 1920×1080 overlay iframe's `requestAnimationFrame` and Long Tasks API during Pump and dump. Each sample lasted 10,007 ms. Normal motion: 1,413 frame intervals, 141.21 FPS average, 6.9 ms median and 7.1 ms p95, one interval over 34 ms, zero long tasks. Reduced motion: 1,431 intervals, 143.01 FPS average, 6.9 ms median and 7.1 ms p95, no intervals over 34 ms or long tasks. This browser follows the approximately 144 Hz display; it is distinct from the 60 FPS OBS output. JSON results and a screenshot are saved in `artifacts/h3/`. The prior Chrome Performance trace is described in [E4](e4-overlay.md).
